fix(server): keep idle connections alive while the DSP blocks the event loop

The microservice runs embed/detect synchronously on the main thread, so a request can
block the event loop for seconds. Node's default 5 s server.keepAliveTimeout then races
a client that reuses a pooled connection: the socket is closed just as the queued
request arrives, and the client sees ECONNRESET.

Reproduced by running two test suites concurrently (a stand-in for a busy CI runner):
"binary embed preserves 24-bit PCM word depth", "custom numeric band 'lowHz:highHz' is
accepted" and "unsupported output format is rejected with 400" all failed with
fetch failed / ECONNRESET. After raising keepAliveTimeout (120 s), headersTimeout
(125 s) and requestTimeout (600 s) on the server, both concurrent suites pass 121/2.

Also adds the ffmpeg probe result to the test workflow's dependency list and records
the fix in AUDIT_REPORT.md section 10.
